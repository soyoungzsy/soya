# SOYA 卡片仓 Skill

> 与 `personal-board`（个人董事会）、`soya-morning-meeting`（每日晨会）配套使用，构成完整的 SOYA 自我管理体系。

## 🎯 定位

**卡片仓**是你个人知识的"资产库"：把读过的方法论、踩过的坑、总结出的判断、复盘出的经验，沉淀成**小而精、可复用、可检索**的知识卡片。长期坚持，你的卡片仓就是你最值钱的"第二大脑"。

**一句话**：让每一次经历都不白费，让每一条经验都能被未来的你调用。

## ⚙️ 配置

首次使用前，告诉你的 AI 助手你的**本地知识库路径**：

```
我的知识库根目录是：/path/to/your/vault
卡片仓写入：<你选择的目录>/卡片仓/
```

未配置时，卡片以 Markdown 形式直接输出，由你手动归档。

## 🗂️ 卡片仓结构（建议）

```
卡片仓/
├── 01_方法论笔记/     # 可复用的方法、流程、框架
├── 02_知识卡片/       # 概念、原理、摘录+思考
├── 03_案例卡片/       # 真实案例、复盘、决策回顾
└── 04_项目复盘/       # 项目级经验沉淀
```

> 结构可按个人习惯调整，**不为了沉淀而过度建目录**；先用已有结构，必要时小步新增。

## 📥 什么值得沉淀成卡片？

| 类型 | 例子 | 落点 |
|------|------|------|
| **方法论** | "向上沟通的三段式话术"、"决策的逆向检查清单" | 01_方法论笔记 |
| **知识** | "第一性原理是什么"、"MECE 原则" | 02_知识卡片 |
| **判断** | "这个项目失败的原因"、"哪种老板值得跟" | 03_案例卡片 |
| **复盘** | "Q3 项目复盘：什么有效、什么无效" | 04_项目复盘 |

**筛选标准（至少满足一条）**：
- 未来 3 个月大概率会用到的
- 具有可复用模式的
- 花了大代价（时间/金钱/情绪）换来的经验
- 反复出现的问题

## ✍️ 卡片写作规范

每张卡片遵循 **"一句话主题 + 结构化正文 + 可执行落点"**：

```markdown
# 卡片标题（一句话说清是什么）

## 核心要点
- 
- 

## 适用场景 / 反例
- 适合：
- 不适合：

## 行动落点
- 下次遇到 X 场景时：做 Y

## 来源
- （可选）哪次经历 / 哪本书 / 哪位董事会成员的建议
```

### 规范要求

1. **小而精**：一张卡片只讲一件事，200-500 字为宜
2. **可执行**：每张卡片必须有"行动落点"，否则只是收藏不是沉淀
3. **反例意识**：写清楚"什么时候不适用"，避免误用
4. **诚实脱敏**：涉及真实人事时统一脱敏为"组织变化"、"关键评价节点"、"协作关系调整"等中性表述

## 🎓 卡片治理流程（圆桌决策）

当晨会识别出需要沉淀的能力项时，按以下优先级决定沉淀方式（由"董事会"圆桌讨论决定）：

1. **只保留在日会纪要**（信息量小，不必单独成卡）
2. **抽成一张行动卡/判断卡/沟通话术卡**（最常用，推荐）
3. **写成方法论笔记**（信息量大、可系统化）
4. **在长期主义中新增一个小模块或索引入口**（成为体系的一部分）

### 默认能力标签

沉淀时可打上能力标签，方便检索：
`业务判断`、`向上管理`、`组织协同`、`关键沟通`、`情绪稳定`、`AI杠杆`、`产品判断`、`长期节奏`

## 🧹 边界与治理原则

- **不删除**、不重命名、不批量移动已有文档，除非用户明确要求
- **不长期记录**敏感职场细节、具体人事信息；统一脱敏为中性表述
- **不为了沉淀而沉淀**：先想清楚"这张卡片未来谁会看、什么时候看"
- **定期回顾**：每月翻一次卡片仓，合并重复卡片、删除失效卡片、升级高频卡片为方法论

## 🔄 配套使用

| 场景 | 用什么 |
|------|-------|

对 AI 助手说：

```
帮我沉淀一张卡片：<描述这次经历/这个判断>
```

或：

```
把最近的项目复盘写进卡片仓。
```
